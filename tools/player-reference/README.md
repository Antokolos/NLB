# Эталонные прохождения для сверки Java-плеера с NLBNavigator

Java-плеер проверяется так: тот же ввод, что получил консольный плеер NLBNavigator (`nlb_main`),
должен дать тот же журнал прохождения. Эталоны лежат в
`NLBL/src/test/resources/player-reference/<книга>/walk-N.{input,log}`, манифест —
`manifest.properties` (коммиты NLBNavigator и книг).

## Пересобрать эталоны

```bash
tools/player-reference/make-reference.sh
```

Скрипт скачивает NLBNavigator на коммите из `make-reference.sh`, собирает `nlb_main` без SDL,
скачивает книги из `books.txt` (с подмодулями — внешними модулями книг) и делает по несколько
случайных прохождений `walk.py`. Нужны git, cmake, ninja, C++-компилятор и python3.

- `NLB_REFERENCE_CACHE` — куда скачивать (по умолчанию `~/.cache/nlb-player-reference`);
- `NLB_TEST_BOOKS` — каталог книг (по умолчанию `<кэш>/books`). Его же читают тесты Java.

Прохождения воспроизводимы: при тех же коммитах повторный запуск даёт те же файлы. Каждый прогон
идёт с отдельным временным `HOME`, поэтому достижения и сохранения прошлых прогонов
(`~/.nlbnavigator`) не влияют на журнал.

## Как устроено прохождение

`walk.py` играет за игрока: читает экран `nlb_main`, выбирает случайное действие — переход
(`N`), объект на сцене (`oN`), предмет инвентаря (`iN`), применение (`uN oM` / `uN iM`),
ожидание (`w`) — и записывает ввод. Сначала по весу выбирается вид действия (переходы — чаще,
чтобы двигался сюжет), затем действие этого вида. Прохождение заканчивается в конце игры или
по лимиту случайных шагов (`books.txt`).

### Сценарии

Где случайный игрок не доходит до нужных мест (в «Слуге Ра» он гибнет раньше, чем срабатывают
autowired-страницы), прохождение начинается по сценарию
`scripts/<книга>/walk-N.script` — для прохождения с тем же номером. Строки сценария — по тексту,
а не по номерам, которые меняются от экрана к экрану:

- `go Холл` — переход по варианту с этим текстом;
- `obj кнопка` — объект сцены, имя которого начинается с этого текста;
- `inv Задания` — предмет инвентаря;
- `use Ключ > дверь` — применить предмет к объекту или предмету;
- `obj кран #2` — второй из объектов с таким именем (так же для `inv` и `use`);
- `o4`, `1`, `w` — команда `nlb_main` как есть;
- строка, начинающаяся с `#`, — комментарий.

Если действия сценария на экране нет, но есть «Далее», нажимается «Далее». Если нет и его,
`walk.py` останавливается с ошибкой и показывает экран. После сценария игра идёт случайно.

### Случайность

`nlb_main` запускается с `--deterministic`: случайность книги воспроизводима — k-й вызов
`rnd(n)` даёт `(k mod n) + 1`, `SHUFFLE` разворачивает список (`PlayerContext::setDeterministic`
в NLBNavigator). Java-плеер в режиме сверки должен давать ту же последовательность. На книги без
`RND`/`SHUFFLE` ключ не влияет.

## Тесты

`ReferenceDataTest` (NLBL) проверяет, что эталоны на месте, и, если книги скачаны, что Java
загружает их так же, как C++ (строка `Loaded:` журнала). Без книг эта проверка пропускается:

```bash
NLB_TEST_BOOKS=~/.cache/nlb-player-reference/books mvn -pl NLBL test
```

# Внешние модули книги и git

Внешний модуль — отдельная книга NLB, которую книга-родитель подключает страницей-модулем с
флажком «external». Редактор, экспорт и плееры ищут такие модули в каталоге `modules/<имя>`
книги-родителя.

## Как подключать: подмодули git

Раньше каталог `modules/` был в `.gitignore` книги (редактор создавал его при первом
сохранении), а автор вручную клонировал туда репозитории модулей. Чтобы передать книгу другому
человеку, приходилось объяснять, что и куда положить. Теперь модули подключаются подмодулями
git в репозитории книги:

```
git submodule add https://github.com/<владелец>/<модуль>.git modules/<модуль>
git commit -m "Модуль <модуль>"
```

и книга скачивается целиком одной командой:

```
git clone --recurse-submodules https://github.com/<владелец>/<книга>.git
```

Редактор больше не создаёт `.gitignore` с `/modules/` (такое правило мешало `git submodule
add`); в старых книгах эту строку из `.gitignore` нужно убрать вручную.

## Как скачать книгу (Clone)

Кнопка **Clone** на панели (рядом с «Открыть»): адрес книги (`https://github.com/<владелец>/<книга>`
или `git@github.com:<владелец>/<книга>.git`) и папка (по умолчанию — имя из адреса в прошлой
выбранной папке). Книга скачивается вместе с внешними модулями на любую глубину (то же, что
`git clone --recurse-submodules`; модули — на ветке, push из редактора работает сразу) и
открывается. Устанавливать git не нужно (JGit).

- По https — сначала с сохранённым токеном этого сервера, а если его нет — без учётных данных:
  открытые книги скачиваются без вопросов. Сервер потребовал вход или не принял токен — диалог
  «User name / Password or token / Remember», как у push, и повтор.
- По ssh — ключи, ssh-agent, known_hosts и пароль к ключу, как у pull и push.
- Не удалось — папка, которую создало скачивание, удаляется (повтор не упрётся в непустую папку);
  непустую папку выбрать нельзя.

## Как опубликовать книгу (Publish)

Кнопка **Publish** (глобус со стрелкой, после Push) — первая отправка книги на сервер, без
браузера и без установки git. Книга должна быть сохранена; если у неё уже есть адрес сервера
(origin), редактор так и скажет и предложит Commit и Push. Незакоммиченные изменения (или книга
без единого коммита) коммитятся перед отправкой — сообщение коммита в том же диалоге
(«First version of the book»); не задан автор коммитов — его спросят, как у Commit.

Два варианта:

- **Create a new repository on GitHub.** Имя репозитория — из имени папки книги (латиница,
  цифры, `-`, `_`, `.`; остальное заменяется на `-`), владелец — свой аккаунт или организация,
  описание — название книги, флажок «Private» (по умолчанию включён; выбор запоминается).
  Нужен токен GitHub: classic — с правом `repo`; fine-grained — доступ ко всем репозиториям и
  права «Administration» и «Contents»: Read and write. Токен спрашивается один раз и хранится в
  системном хранилище секретов под `https://github.com` — тем же токеном потом работают Push,
  Pull и Clone. Редактор проверяет токен (`GET /user`), создаёт пустой репозиторий
  (`POST /user/repos` или `/orgs/<организация>/repos`, без README), записывает его адрес в книгу
  и отправляет её. Не принят токен — спросит снова (сохранённый забывается); имя занято, нет
  прав, нет организации — сообщение с объяснением. Репозиторий создан, но отправка не удалась —
  адрес остаётся в книге, повторить можно кнопкой Push.
- **Use an existing empty repository** — адрес уже созданного пустого репозитория на любом
  сервере (GitLab, Gitea, свой; https или ssh). Учётные данные — как у Push. Отправка не удалась
  или отменена — адрес из книги убирается (возможно, в нём ошибка), можно повторить Publish.

После отправки ветка книги связана с сервером (как `git push -u origin <ветка>`): Pull и Push
работают сразу. Внешние модули (подмодули) отправляются в свои репозитории, как при Push, — их
адреса публикация не меняет.

Для проверки без настоящего GitHub адрес API задаётся свойством `-Dnlb.github.api=<адрес>`
(по умолчанию `https://api.github.com`; GitHub Enterprise — `https://<сервер>/api/v3`), а сервер,
под которым хранится токен, — `-Dnlb.github.server=<адрес>` (по умолчанию `https://github.com`).

## Как править внешний модуль

- **Прямо в книге-родителе.** Вкладка внешнего модуля из `modules/` самой книги (подключённого её
  страницей или страницей её внутреннего модуля) помечена «(external)» и правится как обычная.
  Она показывает копию модуля (страница книги держит её в своём модуле), а при сохранении книги
  правки из копии переносятся в книгу модуля (страницы, объекты, переменные, стартовая точка,
  порядок автопереходов; `NonLinearBookImpl.takeContentFrom`), и та сохраняется в
  `modules/<модуль>` — так же, как при открытии модуля отдельной книгой: свойства модуля, его
  медиафайлы и его собственные внешние модули не меняются. Файлы попадают в индекс git
  подмодуля (свой адаптер VCS, `VCSAdapter.newAdapter`); сама книга-родитель модуль не пишет.
- **Только для чтения** («(read-only)», с объяснением; перетащенный узел возвращается на место):
  внешний модуль внутри внешнего модуля (он в `modules/` того модуля — откройте тот модуль
  отдельной книгой) и второе подключение того же модуля в книге (две копии разошлись бы —
  правится первая открытая вкладка).
- Внешний модуль можно открыть и **как отдельную книгу**: «Открыть» -> `modules/<модуль>`.
- После `git clone --recurse-submodules` и `git submodule update` HEAD подмодуля отсоединён
  (detached). Редактор при открытии модуля переводит его на ветку с тем же коммитом
  (предпочтение — ветке по умолчанию сервера, затем `master`, `main`; локальная ветка при
  необходимости создаётся или перематывается вперёд). Файлы при этом не меняются. Если такой
  ветки нет, HEAD остаётся отсоединённым, и push объяснит, что сделать (`git checkout <ветка>`).

## Кто коммитит

Коммиты из редактора (книги и её внешних модулей) — от имени и e-mail из настроек git: `user.name`
и `user.email` в `.git/config` клона книги, а если их там нет — из общих настроек git
пользователя (`~/.gitconfig`). Это не свойство книги: в её файлы не попадает, у каждого соавтора
своё. Задаются в свойствах книги («Commit author», «Commit e-mail»; меняются, только если их
поправить, — общие настройки в `.git/config` не копируются; пустые поля убирают настройку из
`.git/config`). Если не задано нигде, редактор спрашивает их перед первым commit и записывает в
`.git/config` книги. Внешние модули коммитятся от того же имени, что и книга.

## Пароль или токен для pull и push

Pull и push — по https. GitHub (как и большинство серверов) пароль учётной записи для git не
принимает: нужен токен доступа (Settings -> Developer settings -> Personal access tokens ->
Fine-grained tokens; доступ к репозиториям книги и её модулей, Contents: Read and write). Его
вставляют в поле «Password or token».

- **Запомнить** — токен хранится в системном хранилище секретов: Windows — диспетчер учётных
  данных, macOS — связка ключей, Linux — Secret Service (GNOME Keyring, KWallet) через libsecret.
  Устанавливать git или другие программы не нужно (вызовы ОС — через JNA,
  `com.nlbhub.nlb.vcs.secrets`). Токен зашифрован системой и привязан ко входу пользователя; в
  файлах книги и настройках редактора его нет. Имя пользователя на сервере (не секрет)
  запоминается в настройках Java пользователя. Запись — по серверу (`https://github.com`) и имени:
  внешние модули с того же сервера используют тот же токен.
- Если токен запомнен, pull и push идут без вопросов. Сервер его не принял (отозван, истёк, нет
  прав на запись) — редактор удаляет его из хранилища и спрашивает снова.
- Нет хранилища (Linux без libsecret или без сеанса D-Bus) — «Запомнить» недоступно, токен
  спрашивается каждый раз.

## Pull и push по ssh

Если книга склонирована по ssh (`git@github.com:<владелец>/<книга>.git`), пароль и токен не нужны:
редактор (JGit + Apache MINA SSHD, без установки git и ssh) входит по ключу.

- Ключи — из `~/.ssh` пользователя (на Windows — `%USERPROFILE%\.ssh`): `id_ed25519`, `id_rsa` и др.
  Открытый ключ (`….pub`) должен быть добавлен на сервере (GitHub: Settings -> SSH and GPG keys ->
  New SSH key). Нет ключа — `ssh-keygen -t ed25519` (есть в Windows 10+, macOS и Linux).
- **ssh-agent** — если запущен (Pageant или агент OpenSSH в Windows, `SSH_AUTH_SOCK` в Linux и
  macOS), ключи берутся из него, и редактор ничего не спрашивает.
- **Пароль к ключу** (если ключ зашифрован и агента нет) — редактор спрашивает и может запомнить
  его в системном хранилище секретов (как токен; запись — по пути к файлу ключа). Не подошёл —
  «The passphrase is not correct», запомненный забывается.
- **Незнакомый сервер** — вопрос с отпечатком его ключа (SHA256); согласие записывает ключ в
  `~/.ssh/known_hosts`, дальше вопроса нет. Ключ сервера изменился — соединение отклоняется с
  сообщением.
- Сервер не принял ключ — сообщение, что проверить (ключ на сервере, ключ в агенте).

## Кнопки VCS книги-родителя

- **commit** книги сначала коммитит (тем же сообщением) модули, сохранённые из неё после
  прошлого commit, затем книгу — с новыми коммитами модулей (ссылкой на коммит подмодуля).
  Незакоммиченные правки модуля, сделанные не из книги (модуль открывали как книгу), в commit не
  попадают — о таких модулях предупреждение в логе.
- **push** книги сначала отправляет модули с неотправленными коммитами, затем книгу: книга не
  сошлётся на коммит модуля, которого нет на сервере. Отклонённый сервером push (на сервере есть
  чужие коммиты) — ошибка с советом сделать pull.
- **pull** книги обновляет и модули — на записанные в книге коммиты (недостающее скачивается),
  и переводит их на ветку. Модули с незакоммиченными правками не трогаются — о них сообщение.

Обычный порядок: открыть книгу -> править модуль на его вкладке -> сохранить -> commit -> push
(модуль коммитится и отправляется вместе с книгой). То же из командной строки:
`git -C modules/<модуль> commit -am ...`, `git add modules/<модуль>`, `git commit`,
`git push --recurse-submodules=on-demand`.

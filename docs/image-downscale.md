Уменьшение картинок в Media Library («Downscale...»)
====================================================

Зачем: картинка больше экрана игры обрезается. Спрайт VN рисуется в своём размере (не
масштабируется ни в INSTEAD, ни в NLBNavigator, ни в веб-плеере), и спрайт 1086×1448,
привязанный к низу экрана 1920×1080, теряет сверху 368 px — голову персонажа (CoolAir-Images).
Кнопка уменьшает такие картинки в самой книге, один раз, вместо уменьшения при каждом показе.

## Как пользоваться
Media Library картинок (свойства страницы или объекта -> «Картинка…») -> выделить файлы ->
**Downscale...** -> задать «Fit into: width / height» (по умолчанию 1920×1080, экран VN; 0 — без
ограничения) -> проверить таблицу -> **Downscale**.

## Правила
- **Один коэффициент на группу** — по самой большой картинке выделения:
  `k = min(1, W / наибольшая ширина, H / наибольшая высота)`. Ракурсы одного персонажа остаются
  одного масштаба (персонаж не «растёт» от позы к позе), поэтому выделять их нужно вместе.
- **Только уменьшение.** Если всё уже помещается — «All images already fit», кнопка неактивна;
  повторный запуск ничего не меняет.
- **Кадры анимации** уменьшаются все вместе: у анимированной картинки страницы или объекта в книге
  записано имя последнего кадра (`intro-1478.jpg` -> кадры `intro-1.jpg` … `intro-1478.jpg`,
  правило — `ExportManager.FILE_NAME_PATTERN`, то же, что у экспорта). Выделенный кадр добавляет
  в группу всю серию (пометка «animation frame»). Файлы с номером в имени, которые нигде не
  анимированы, серию не тянут.
- **Переадресации** (`.redirect`): уменьшается цель — её и показывает игра (пометка «redirect
  target of …»).
- **Формат и имя сохраняются:** PNG — PNG с прозрачностью, JPG — JPG (качество 95: это исходник
  книги, сжимает его экспорт по пресетам `.preset`), BMP — BMP. GIF и нечитаемые файлы не
  трогаются (причина — в таблице). Ссылки страниц и объектов, `.preset`, `.constrid`,
  `.redirect` остаются верными.
- **Качество:** шагами не больше чем вдвое (билинейно), последний шаг — бикубически; прозрачность —
  в премультиплицированном виде, без тёмной каймы по краю спрайта.

## Предупреждения
Положения в пикселях не пересчитываются. Диалог перечисляет объекты с картинками группы, у
которых:
- задано смещение (`offset`, кроме `0,0`) — проверить положение после уменьшения;
- есть вложенные объекты — их координаты в пикселях картинки родителя, и после уменьшения
  родителя они сместятся относительно неё.

## Запись и откат
Файлы перезаписываются на диске сразу (через временный файл рядом и замену — при сбое не
остаётся недописанного), без undo редактора: undo — для модели книги, а не для файлов. Книга под
git: уменьшенные файлы отмечаются в индексе как изменённые и попадают в коммит из редактора;
вернуть оригиналы — средствами git. Книга только для чтения (копия внешнего модуля) — ничего не
меняется.

## Устройство
- `NLBL`, `com.nlbhub.nlb.util.ImageDownscaler` — без Swing: `plan` (размеры из заголовков
  файлов), `replan` (те же файлы с другими ограничениями, без диска — кадров бывают тысячи:
  заставка «Фронтира» — 1478, чтение заголовков ~1,4 с), `apply`, `group` (кадры и
  переадресации), `animatedImageNames`, `offsetWarnings`. Тесты — `ImageDownscalerTest`.
- `NonLinearBookFacade.downscaleImageFiles` — запись и отметка в VCS
  (`FileManipulator.markModified`).
- `NLBB`: `DialogDownscaleImages` (диалог), кнопка `m_buttonDownscale` в `DialogMediaLibrary`.

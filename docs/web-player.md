# Веб-плеер NLBW: аудит и план

Цель — плеер на Java, который играет книги так же полно, как экспорт в INSTEAD (см. `CLAUDE.md`).
Этот документ — исходная точка: что есть сейчас, чего нет, что переиспользовать, план по этапам.

## Итог в двух словах

- **Модель книги в NLBL полная**: страницы, ссылки, объекты, модификации всех 57 типов, модули
  (включая внешние — при загрузке они копируются в страницу-модуль), autowired-свойства,
  медиа и их условия/переадресации/пресеты/флаги, многоязычные тексты, достижения. Читать книгу
  заново не нужно.
- **Правил игры в Java почти нет.** Старый плеер NLBW выполняет только `ASSIGN`, не знает
  объектов, инвентаря, autowired, таймеров, достижений, сохранений, картинок и звука. Его
  устройство (перепроигрывание всей истории на каждом ходе, общее `static`-состояние, XML + XSL)
  не подходит как основа — ядро нужно писать заново.
- **Эталон есть и исполняется**: экспорт INSTEAD (`ExportManager` + `STEADExportManager` /
  `VNSTEADExportManager` + `nlb.lua`) и NLBNavigator, где эта семантика уже реализована на C++
  (`PlayerEngine` ≈2150 строк, `PlayerContext` ≈980, `ModificationInterpreter` ≈1250 — все типы
  модификаций, слой экрана `NLBPresentation` ≈3100). Консольный `nlb_main` из NLBNavigator
  **собирается в облачной сессии** (`cmake -DNLB_WITH_SDL3=OFF`) и пишет журнал прохождения
  (`--log`), значит, сверку Java с C++ можно автоматизировать.

## Как устроен старый плеер

`NLBW/.../GetNLBDataService` (730 строк) + `NonLinearBookImpl.createFilteredPage` (NLBL):

- REST: `/{bookId}/start`, `/page/{id}`, `/link/{pageId}/{linkId}`, `/history`; модуль кодируется
  в `bookId` матричными параметрами (`book;1=pageId;2=...`).
- Состояния игры нет: на каждый запрос `createFilteredPage` заново проигрывает весь журнал
  решений (`History` / `DecisionPoint`) и считает переменные. Цена хода растёт с длиной игры.
- Из модификаций выполняется только `ASSIGN` (`updateVisitedVars`: «TODO: Other modification
  types»). Переменная страницы и ссылки ставится в `true`. Таймер — «TODO: page timer???».
- Выражения — движок JavaScript (`ScriptEngineManager`), неизвестная переменная = `false`.
- Ссылки: обычные, `once` (по журналу), ограничения, ограничение модуля, auto (первая
  автоссылка выполняется сразу), служебные Traverse/Return для внутренних модулей, MPL.
- Объекты: текст объектов, лежащих на странице, просто дописывается к тексту страницы.
- Вывод: страница сериализуется JAXB в XML и превращается в HTML через `xsl/page.xsl`
  (заголовок, текст, ссылки) + iframe с историей (`xsl/history.xsl`). Картинок и звука нет.
- Глобальное состояние: `static History s_history`, `static m_nlbCache`, корень библиотеки
  `s_nlbLibraryRoot = "/D:/work/Azartox/NLB/books/"`; XSL и `cfg` ищутся от текущего каталога.
  Один игрок на сервер.
- Используется только из редактора: `MainFrame` кладёт книгу в кэш и открывает `/start`.

## Что переиспользовать

- **Модель и загрузка книги** NLBL — как есть.
- **`ExportManager`**: построение служебных ссылок модулей и autowired, тривиальность ссылок,
  `isInlineLink`, значения переменных по умолчанию (`getInitValuesMap`), карты медиа. Часть этой
  логики `private` и завязана на генерацию текста — вынести общее в доступные методы без
  изменения поведения экспорта.
- **`VNSTEADExportManager.getPreprocessedChunks`** — порции текста VN (сейчас `private`).
- **`PropertyManager` / `cfg/config.xml`** — тексты по умолчанию и needs-action-count.
- **`MultiLangString`** и выбор языка из `LanguageHelper` (NLBB) — для выбора языка игроком.
- **Jetty + Jersey** в NLBW и `Launcher` — оставить как веб-слой.
- Старые `History`, `DecisionPoint`, `createFilteredPage` — **не** использовать в новом ядре.

## Принятые решения

1. **Вычисление выражений** — свой вычислитель для синтаксиса условий NLB (`== != < <= > >=
   && || !`, числа, строки, переменные, `true/false`, скобки, арифметика), поведение — как в
   C++ (cparse). Не движок JavaScript: семантика INSTEAD отличается от JS в мелочах —
   отсутствующая числовая переменная делает условие ложным (`translateExpressionBody`
   добавляет проверки существования), строки и числа сравниваются по правилам Lua.
2. **JSON** — Jackson (`jersey-media-json-jackson`).
3. **Сохранения и достижения** хранятся у игрока: снимок — JSON, API отдаёт и принимает его,
   клиент по умолчанию хранит в `localStorage`, сервер ничего не хранит. Так плеер можно
   выложить для многих игроков без учётных записей.
4. **Режим по умолчанию — VN**, как в C++ (`ExportMode::VN`: тема DEFAULT = VN); STANDARD —
   по выбору при запуске.
5. **Старый плеер**: новый живёт на отдельных адресах (`/play/...`), редактор переключается
   на него после этапа 5, старый удаляется последним этапом.

## План по этапам

Каждый этап — отдельный PR с тестами. Ядро (этапы 1–4) — пакет `com.nlbhub.nlb.player` в NLBL,
без зависимостей от веба.

**Этап 0. Стенд для сверки.**
Тестовые книги (ваши каталоги и маленькие синтетические, собранные из Java через
`NonLinearBookFacade`); скрипт: собрать `nlb_main`, пройти книгу по сценарию выборов, записать
журнал. JUnit в NLBL (в зависимостях уже есть JUnit 4).
*Приёмка:* `mvn test` запускает тесты; для каждой тестовой книги есть эталонный журнал C++.
*Сделано:* `tools/player-reference` (см. README там): `make-reference.sh` собирает `nlb_main`
на зафиксированном коммите NLBNavigator, скачивает книги wolfman, barbarian_caves_demo,
chaperonrougehub (с внешним модулем `chaperon_filling_hub` — git-подмодуль), servant-of-ra
(тема STANDARD), Frontier (тема STANDARD, три внешних модуля-подмодуля), wild-island-quest
(картинки по тегу страницы и переадресации) и синтетическую bookU и делает по 5 прохождений `walk.py`
— случайных или начатых по сценарию (`scripts/`); пары «ввод + журнал» — в
`NLBL/src/test/resources/player-reference`. Случайность книг воспроизводима
(`nlb_main --deterministic`: k-й `rnd(n)` = `(k mod n) + 1`, `SHUFFLE` разворачивает список) —
Java-плеер в режиме сверки должен вести себя так же. `ReferenceDataTest` проверяет эталоны и
загрузку книг в Java. В книгах есть модули (вложенные и внешние), объекты, инвентарь,
контейнеры, теги, клоны, списки (PUSH/POP/SIZE/SHUFFLE…), WHILE, RND, таймеры страниц,
достижения, условия и переадресации картинок (выбор картинки по тегу страницы — в
wild-island-quest), анимацию, autowired (все пять страниц «Слуги Ра»
— по сценариям; глобальный и во внешних модулях), needs-action, callback-объекты, COUNTGET,
обе темы; не всё из этого встречается в случайных прохождениях — непокрытое добирается
сценариями и синтетическими книгами в JUnit на этапах 1–2.

**Этап 1. Ядро: навигация и модификации без объектов.**
Состояние сессии (переменные, списки, счётчики), вычислитель выражений, все модификации,
не связанные с объектами, страницы и ссылки (ограничения, once, auto, needs-action, alt-текст,
переменные страниц и ссылок, `$var$`), модули (внутренние, внешние, Traverse/Return, MPL,
ограничение модуля), autowired, таймер страницы, GOTO/RETURN, язык книги. Консольный запуск
ядра с журналом в формате `nlb_main`.
*Приёмка:* журналы Java и C++ совпадают на книгах без объектов; JUnit на каждый тип модификации.
*Сделано (вместе с этапом 2):* пакет `com.nlbhub.nlb.player` — порт `PlayerContext`,
`ModificationInterpreter`, `PlayerEngine` и `NLBExplorer` из NLBNavigator:
- `Value`, `Expression` — значения и вычислитель выражений с семантикой cparse (типы, `%g`,
  целые/дробные, Lua-синтаксис `and`/`or`/`not`/`~=`/`..`); сверка с самим cparse —
  `ExpressionTest` (эталон строит `tools/player-reference/cparse`);
- `PlayerContext` — переменные, списки, инвентарь, контейнеры, клоны, теги, свёрнутые объекты,
  счётчики COUNTGET, SNAPSHOT, история страниц, случайность (в том числе детерминированная);
  `Achievements` — прогресс достижений отдельно от игры (переживает «Начать заново»);
- `ModificationInterpreter` — все типы модификаций, `$var$`, действия объектов
  (act/use/dsc), картинки и звуки по тегам, `.constrid`/`.redirect`/`.flag`;
- `PlayerEngine` — ссылки как их строит экспорт (Normal, Traverse, Return с MPL, AutowiredIn/Out),
  ограничения, once, auto, needs-action, модули, таймер страницы (тик — ход игрока, без
  выбора время проматывается), GOTO/RETURN, callback-объекты, взять/действие/применить,
  внешние игры (`play_bp_*`), конец игры; события вывода и вид страницы (`view()`);
- `ConsolePlayer` — консольный плеер с выводом и командами `nlb_main explore`
  (`java -cp … com.nlbhub.nlb.player.ConsolePlayer <книга> [vn|standard] --deterministic
  --config NLBW/cfg/config.xml`; в дистрибутиве — `play.sh <книга> [vn|standard]` /
  `play.bat …`, путь к книге — от текущего каталога); настройки экспорта читает новый
  `PropertyManager.readSettings(File)`.

Приёмка: `ReferenceWalkTest` воспроизводит ввод всех 35 эталонных прохождений семи книг и
построчно сравнивает вывод с журналами `nlb_main` — совпадают все; `PlayerEngineTest` —
модификации и навигация на книгах, собранных в памяти (выражения, IF/ELSEIF/ELSE, WHILE, RND,
списки, таймер, once, GOTO и RETURN в ссылке, достижения после «Начать заново», конец игры).

Сверка нашла ошибку в NLBNavigator: в журнале у картинок объектов вместо «— подпись @
положение» печаталось «— положение» (поля события сдвинулись после добавления `Event::id`).
Исправлено там (Antokolos/NLBNavigator#2), эталоны пересобраны на исправленном коммите;
изменились только строки `[IMAGE: …]`/`[ANIMATION: …]`, ввод прохождений — нет.

Отличия от старого кода NLBL, сделанные сознательно (как в NLBNavigator): подстановка `$var$`
в текст режет строки по `\n` и убирает только хвостовые пробелы каждой строки
(`StringHelper` NLBL обрезал и начальные); пробельные символы — как в C (`isspace`).
Пока нет модели экрана (этап 4); сохранения — этап 3.

**Этап 2. Объекты и инвентарь.**
Экземпляры и клоны, контейнеры, взять/действие/применить/nouse, инвентарь, теги, OBJS/ADD*/
REMOVE/CLEAR, тексты game-inv/game-nouse, достижения и perfect game, COUNTGET/COUNTRST.
*Приёмка:* журналы совпадают на книгах с объектами.
*Сделано вместе с этапом 1* (см. выше): все тестовые книги с объектами и инвентарём проходятся
так же, как в C++.

**Этап 3. Сохранения.**
Снимок состояния в JSON, загрузка (страница показывается заново без модификаций), `nosave`,
SNAPSHOT, «Начать заново», достижения отдельно от сохранения.
*Приёмка:* сохранить → загрузить → продолжить даёт тот же журнал, что игра без перерыва.
*Сделано:* `PlayerEngine.saveGame()` → JSON, `loadGame(json)`, `readSaveInfo(json)` (подпись
слота, время, та ли книга), `canSave()` (страница `nosave`). Сохраняется состояние мира, как в
INSTEAD: переменные (с типом: `b:1`, `i:5`, `r:2.5`, `s:…`, `n:`), списки, инвентарь,
контейнеры, клоны, теги, счётчики, история страниц, однократные ссылки, свёрнутые объекты,
состояние случайности (свой генератор SplitMix64 — одно число, поэтому после загрузки
случайность идёт так же, как без перерыва), текущая страница, lasttext, музыка, внешняя игра,
preserved-объекты и снимок SNAPSHOT. Загрузка показывает страницу заново, не исполняя её
модификаций. Достижения в сохранение не входят: `Achievements.toJson()`/`restore(json)` —
отдельно (в браузере это будет localStorage). JSON — Jackson (новая зависимость NLBL).

SNAPSHOT — как в INSTEAD (`make_snapshot` + `_try_again` в nlb.lua): снимок всей игры, тот же,
что сохранение, делается в конце хода; «Попробовать ещё раз» в конце VN-игры
(`PlayerEngine.tryAgain()`) возвращает к нему, а без снимка начинает заново; «Начать заново»
в меню снимок забывает. Отличие от NLBNavigator: там «ещё раз» всегда начинает заново (в
тестовых книгах SNAPSHOT только на стартовой странице wolfman — журналы совпадают).

Консольный плеер: в меню «Сохранить»/«Загрузить» на 9 слотов (как в NLBNavigator), файлы —
`~/.nlbplayer/<книга>.saves/slotN.json`, достижения — `~/.nlbplayer/<книга>.achievements.json`.

Приёмка: `SaveLoadTest` — в каждом из 35 эталонных прохождений на 1/3 и 2/3 пути игра
сохраняется в слот, загружается в новом плеере и продолжается тем же вводом; дальше журнал
строка в строку совпадает с игрой без перерыва (где в этой точке — «осмотреться»). Ломка
восстановления счётчика случайности этим тестом ловится. `PlayerEngineTest` — загрузка в
том же и в новом движке, случайность после загрузки, `nosave`, сохранение другой книги,
SNAPSHOT и «ещё раз», значения и достижения через JSON.

**Этап 4. Модель экрана.**
Аналог `ScreenModel`: STANDARD и VN, порции текста VN и листание, картинки страниц и объектов
(с `.constrid`/`.redirect`, анимация), графические объекты (положение, эффекты, свёртывание),
звук, музыка, озвучка по порциям (в порядке поля), оформление окна, OPENURL.
*Приёмка:* JUnit на модель экрана; сверка с `GameScreen`/`ScreenModel` на тестовых книгах.
*Сделано:* в ядре — всё, что не зависит от рисования; раскладка в пикселях, листание порций,
эффекты появления и звук — дело клиента (этапы 5–6).
- `ScreenModel` — порт ScreenModel.h: раскладка (STANDARD/VN), заголовок и название комнаты,
  картинка страницы (кадр анимации по таймеру), текст страницы абзацами из фрагментов (обычный
  текст и ссылки на объекты `{метка}`), описания объектов, текст модификаций, ответ на последнее
  действие, варианты (недоступные — с alt-текстом), объекты сцены (картинка, morphover, угол,
  offset, arm, iarm, эффект появления, z-порядок, видимость, свёрнутость, подсказки отрисовки),
  инвентарь, оформление окна (WINGEOM/INVGEOM/WINCOLOR/INVCOLOR), таймер, конец игры, nosave,
  внешняя игра; `toJson()` — с именами полей ScreenModel.h.
- `PlayerEngine.screen()`, реальное время: `Settings.realTime`, `advanceTime(ms)` (тик таймера
  страницы — 200 мс, у анимации — 40 мс), `timerIntervalMs()`.
- `TextPortions` — порции текста VN (`ScreenModel.portions()`), порт GameScreen::portionsOf.
- `PlayerSession` — сессия игрока для веб-клиента (порт Session без звука и рисования):
  правила щелчков INSTEAD (выбор предмета, повторный щелчок — осмотр, предмет к объекту или
  предмету), события, очередь озвучки страницы в порядке поля, текущая музыка, сохранения,
  «ещё раз».

Приёмка: `ScreenModelReferenceTest` — снимок экрана Java на каждом шаге всех 35 эталонных
прохождений поле за полем совпадает с PlayerEngine::screen() NLBNavigator, вместе с порциями
текста VN (эталон — `tools/player-reference/screen`, 1,1 МБ в gzip). `PlayerSessionTest`,
`TextPortionsTest` — щелчки, реальное время, озвучка, недоступные ссылки, JSON, порции.

**Этап 5. Веб-слой и клиент STANDARD.**
REST (JSON) поверх ядра: сессии игроков, команды, снимок экрана, сохранения; отдача медиа
книги; библиотека книг (каталог на сервере) и книга из редактора; чтение `.nlbpack`. Клиент на
HTML/CSS/JS для темы STANDARD. Редактор переключается на новый плеер.
*Приёмка:* книга проходится в браузере; два игрока играют одновременно независимо; кнопка
запуска в редакторе открывает новый плеер.
*Сделано:* пакет `com.nlbhub.nlb.web.player` (NLBW) — сервлет на `/play/*` того же Jetty, что
старый плеер (в редакторе — порт 8111), и отдельный сервер `PlayerServer` (в дистрибутиве —
`play-web.sh <каталог с книгами>` / `play-web.bat`, ключи `--port`, `--host`, `--config`).
- `BookLibrary` — книги библиотеки: каталоги книг, пакеты `<книга>.nlbpack` и книга из
  редактора. Загруженная книга во время игры не меняется (состояние партии — в сессии игрока),
  поэтому один экземпляр делят все игроки. Экземпляров — по одному на язык, загружаются при
  первом обращении: язык текстов задаёт сама книга (`NonLinearBookImpl.setPlaybackLanguage` —
  книги и всех её модулей, без команды редактора и записи на диск). Книга из редактора
  запоминается копией (`NonLinearBookImpl.copyForPlayback`: несохранённые правки есть, а правки
  во время игры игроков не задевают); экземпляр на другом языке — тоже копия. Копия играет так же,
  как исходная книга: `ReferenceWalkTest` проходит все эталонные прохождения ещё и на копиях.
- `WebSession` — игра одного игрока: `PlayerSession` ядра, режим (VN/STANDARD), прогресс
  достижений. Смена языка — перенос игры сохранением (`PlayerEngine.exportState`) на экземпляр
  другого языка; страница показывается заново уже на нём. Сессии без обращений 6 часов
  забываются, сессий не больше 10 000.
- REST (JSON): `GET /play/api/books`; `POST /play/api/sessions` (книга, режим, языки браузера,
  достижения) → состояние; `GET /play/api/sessions/<id>`; `POST /play/api/sessions/<id>/<команда>`:
  `choose`, `object`, `item`, `clear`, `look`, `advance` (реальное время), `restart`, `tryAgain`,
  `finishExternal`, `save`, `load`, `language`. Состояние — модель экрана (`ScreenModel.toJson`),
  порции VN, события хода (сообщения, достижения, звук), музыка, достижения. Ошибки —
  `{"error": …}` с кодами 400/404/413/500/503.
- Язык: выбор игрока > `?lang=` > языки браузера > английский > язык книги.
- Медиа — `GET /play/media/<книга>/<файл>` (`BookMedia`: книга важнее модулей, имя ищется с
  каталогом и без); тип картинки — по содержимому (в пакете PNG мог стать JPG с прежним именем).
- `.nlbpack` — `com.nlbhub.nlb.util.BookPack` (NLBL), формат NLBNavigator: пакет распаковывается
  в кэш (`<tmp>/nlb-packs/<имя>-<длина>-<время>`, один раз на версию пакета) без крупных
  медиафайлов — вместо них пустые файлы, а содержимое отдаётся прямо из пакета. Пакет без медиа
  тоже играется (без картинок и звука). Консольный плеер принимает пакет вместо каталога.
  Проверено: прохождения wolfman, «Шапочки» (внешние модули в три уровня) и «Слуги Ра» (пакет
  без медиа) из пакетов, собранных `nlb_main pack`, совпадают с прохождениями из каталогов.
- Клиент (`client/index.html`, `player.css`, `player.js`, без сборки и библиотек): список книг
  с выбором режима (по умолчанию — по теме книги), экран STANDARD как `GameScreen`: картинка
  страницы, графические объекты рядом с ней (без подписей), заголовок-«осмотреться», переходы,
  ответ на действие, текст с объектами-ссылками, варианты, инвентарь с выбором предмета и
  применением, сообщения и достижения, конец игры и «Начать заново»; меню — сохранить/загрузить
  (9 слотов в `localStorage`), начать заново, язык, звук, к списку книг; музыка и звуки;
  таймер страницы и анимация — по реальному времени; клавиши 1–9, Esc. Сессия переживает
  перезагрузку страницы (`sessionStorage`), сохранения и достижения хранятся в браузере.
  VN пока показывается тем же экраном (текст страницы и варианты) — свой клиент VN — этап 6.
- Редактор: кнопка запуска открывает `/play/?book=<книга>&mode=<по теме книги>`; старый плеер
  доступен по прежнему адресу `/nlb/<книга>/start`.

Приёмка: `PlayerServletTest` — список книг и клиент, два игрока независимы, смена языка
сохраняет игру, сохранение и загрузка, ошибки; `BookPackTest` — формат пакета, распаковка,
повреждённые пакеты и пути вне книги. В браузере (Playwright): «Слуга Ра» и «Фронтир» в
STANDARD, wolfman в VN до конца и «Начать заново», смена языка, сохранение и загрузка, игра
после перезагрузки страницы, книги из пакетов — без ошибок и неудачных запросов. Редактор
(`run.sh` под xvfb) запускается, его сервер отдаёт и новый плеер, и старый.

**Этап 6. Клиент VN и звук.**
Фон, порции текста, экран вариантов, графические объекты с эффектами, инвентарь, музыка,
эффекты и озвучка в браузере.
*Приёмка:* ваши VN-книги проходятся в браузере; проверка вами вручную.
*Сделано:* экран VN (`client/vn.js`) — порт `GameScreen::renderVisualNovel` NLBNavigator; в
режиме VN им показываются страницы VN, страницы с темой STANDARD (учебник «Шапочки») — экраном
STANDARD, как в C++.
- Экран 1920×1080, вписанный в окно с полями; картинка страницы — во весь экран.
- Графические объекты — на своих местах по правилам vn.lua (угол привязки, arm, offset, iarm,
  дети столбиком под родителем), в порядке обхода сцены; morphover под курсором; анимация кадров;
  эффекты появления и исчезновения (Fade/Move/Zoom, направление, кадров maxStep − curStep по
  20 мс; эффект родителя — и на детях; на экране вариантов объектов нет). Подписи — как
  draw_hud vn.lua: справа от картинки (+4 +5 px), по вертикали по углу привязки, шрифтом подписей
  vn.lua (STEINEMU 29, строка «== … ==» — 45); объект без картинки — только подпись.
- Полоса текста `vn:geom(8, 864, 1904, 184)` экспорта: полупрозрачная, текст с полями по 240 px,
  выравнивание по ширине, «--» -> «—» и кавычки, как модули dash и quotes STEAD. Текст —
  порциями, как paginator (порции строит сервер, `TextPortions`); ответ на действие продолжает
  порции страницы; щелчок мимо ссылок или пробел — дальше; не уместившиеся строки порции
  листаются, прочитанное не повторяется; после последней порции — экран вариантов, а единственный
  тривиальный вариант («Далее») — сразу переход. Страница без текста — сразу варианты.
- Экран вариантов — панель посередине, варианты с номерами, длинные переносятся с отступом;
  щелчок мимо — назад к тексту. В меню — «Варианты: в тексте» (как в NLBNavigator): весь текст и
  нумерованные варианты в полосе с листанием.
- Инвентарь — строка предметов через « | » на чёрной полосе внизу; кнопка меню — картинка темы
  (`gfx/menubtn_ru.png` для русской книги), меню и сообщения — затемнением поверх сцены.
- Конец игры — сообщение «Конец игры» после последней порции, «Начать заново» — «ещё раз».
- Озвучка по фразам: каждая новая порция — следующий файл поля звука, по порядку
  (`docs/voiceover.md` NLBNavigator).
- Оформление — тема INSTEAD: `ScreenTheme` (NLBW) — порт ScreenTheme NLBNavigator (theme.ini,
  theme_vn.lua: окна, цвета, шрифты, инвентарь, кнопка меню; координаты темы -> 1920×1080).
  Базовая тема — `res/vnstead/themes/default` экспорта, зашитая в jar NLBW (1,8 МБ), или
  `__base_theme__` пакета; тема игры — `__theme__` пакета (`pack --theme`). REST:
  `GET /play/api/books/<книга>/theme`, файлы — `GET /play/theme/<книга>/<base|game>/<путь>`.

Отличие от NLBNavigator: подписи объектов — шрифтом подписей vn.lua (29 px), в C++ — шрифтом
текста (32 px).

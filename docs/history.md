История версий книги («History»)
================================

Зачем: после Commit было непонятно, что произошло — версия сохранилась молча, и не видно ни
истории, ни того, что изменилось. Окно History показывает сохранённые версии книги (коммиты git)
и что в каждой изменилось — словами книги («Page "Pantry": text changed»), а не путями файлов.
Только просмотр: ни переключения на старую версию, ни отката.

## Как открыть
- Кнопка с часами на панели — между Commit и Push.
- После Commit — сообщение «Version saved: "…" (N changes)» и что дальше: «It is saved on this
  computer only: press Push to send it to the server» (или «To share the book, press Publish»,
  если сервера нет), кнопка **Open history**.

## Что показано
**Слева — версии**, от новых к старым (по 100, дальше — «Show older versions…»):
- первой строкой — **Not committed yet**: сохранённые правки, которые войдут в следующий Commit
  (индекс git против последней версии; несохранённое в редакторе сюда не попадает);
- сообщение коммита, «today, 14:32» / «yesterday» / дата, автор;
- **only on this computer** (оранжевым) — версия ещё не отправлена, **on the server** (зелёным).
  Признак — по последнему известному состоянию сервера (origin/&lt;ветка&gt; после прошлых pull или
  push), в сеть окно не ходит; без сервера пометки нет;
- слияние при pull — одной строкой **Changes from the server (Anna, 2 versions)**: изменения —
  относительно нашей прежней версии, отдельные версии соавторов не показываются (первая линия
  истории).

**Справа вверху — изменения выбранной версии** по элементам книги:
- **Added / Changed / Deleted** + элемент: настройки книги, страница, ссылка, объект, модификация,
  переменная, картинка или звук (с её .preset/.flag/.constrid/.redirect), внешний модуль; внутренний
  модуль — «Module "…" -> Page "…"»;
- под элементом — поля («text (ru) — changed», «image — added»); четыре файла положения на схеме —
  одной строкой;
- перемещения на схеме и порядок (ссылок, модификаций, объектов), версия редактора — шум: на игру не
  влияют, свёрнуты в строку «Moved on the scheme or reordered: N items» (и серым внутри элементов);
- больше 20 элементов одного вида — группой: «Added 2830 images».

Имена — из открытой книги. Элемента в книге уже нет (удалён) — из файлов той версии: удалённая
страница — своим заголовком (или текстом). Объект без имени (спрайт VN) — по картинке, с местом:
«Object "mrsherrero.png" on page "Horror"» (спрайты одной картинки на разных страницах
различимы). Страница-модуль без текста — по имени модуля.

**Справа внизу — выбранное:**
- поле с текстом — **Before / After** рядом, с подсветкой изменённых слов (как в окне слияния);
- картинка — миниатюры «было / стало» с размерами («Before (1086×1448)», «After (713×950)»):
  уменьшенный спрайт на глаз не отличить;
- элемент (или несколько полей) — таблица «поле / было / стало»: ссылки на элементы — именами
  («container: Page "Smile"»), флажки — on/off;
- звук, внешний модуль — словами («The sound file is replaced», «The external module is updated to
  another version»).

Книга открыта не на основной ветке (не master/main) — предупреждение вверху окна. Окно модальное:
пока оно открыто, книга не меняется; **Refresh** — перечитать.

## Go to element
Кнопка **Go to element** (и двойной щелчок по элементу или его полю) закрывает окно и показывает
элемент по центру схемы, как переход из поиска (`MainFrame.goTo`):
- страница, объект, ссылка — сам элемент; модификация — её владелец (страница, ссылка, объект);
  настройки внутреннего модуля — страница-модуль;
- элемент во внутреннем модуле — на вкладке модуля; закрытая вручную вкладка открывается снова (на
  любой глубине вложенности);
- переменные, картинки, звуки, внешние модули и настройки книги на схеме не нарисованы — кнопка
  неактивна; удалённый в этой версии элемент — тоже;
- элемента уже нет в книге (удалён позже) — сообщение «This element is not in the book now», окно
  остаётся.

Цель перехода по папке элемента — `BookHistory.navigation` (NLBL, с тестом), переход —
`MainFrame.goToElement`, `GraphEditor.goTo` сообщает, нашёлся ли элемент.

## Скорость
Список версий — без чтения содержимого (Frontier: 50 версий за ~10 мс). Изменения версии
считаются в фоне при выборе: обычная версия — десятки миллисекунд; самая большая версия Frontier
(вся книга, 7522 элемента) — около секунды. Для этого: файлы — словарём по элементам, папки версии —
одним обходом дерева, размер файла — без чтения содержимого, имя элемента, добавленного или
удалённого целиком, — только из его файлов.

## Устройство
- `NLBL`, пакет `vcs`:
  - `BookVersion`, `BookFileChange`;
  - `VCSAdapter.getHistory`, `getVersionChanges`, `readVersionTexts`, `listVersionFiles`,
    `readVersionObject`, `getBranchName` (по умолчанию — пусто: без VCS и у Mercurial);
  - реализация — `GitHistory` (JGit, только чтение); `GitAdapterWithPathDecoration` передаёт вызовы.
- `NLBL`, пакет `domain`:
  - `BookHistory.group` — файлы по элементам, добавлен/удалён/изменён, шум, имена, ссылки;
  - `BookFilePaths` — названия полей, имена элементов вне книги (`Names`), `inBook`;
  - `NonLinearBookFacade.getHistory`, `getVersionChanges`, `readVersionObject`, `getBranchName`.
- `NLBB`: `DialogHistory` (окно), `WordDiff` (подсветка слов — общая с `DialogMergeConflicts`),
  кнопка `m_historyButton` и сообщение после Commit (`reportCommit`) в `MainFrame`, значок
  `common/history.png`.
- Тесты: `GitHistoryTest`, `BookHistoryTest`, `BookHistoryFacadeTest` (на bookU в git).
